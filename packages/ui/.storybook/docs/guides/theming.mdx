# Theming

Light and dark are built in, and CSS does the switching. The design system ships no theme script.

## Themes

| Theme  | How to get it                                   | Result                                                 |
| ------ | ----------------------------------------------- | ------------------------------------------------------ |
| System | No `data-theme` attribute (the default)         | Follows the operating system, and changes with it live |
| Light  | `data-theme="light"` on `<html>` or any element | Light on that element and everything inside it         |
| Dark   | `data-theme="dark"` on `<html>` or any element  | Dark on that element and everything inside it          |

Themes nest, so one region can differ from the page:

```html
<html data-theme="dark">
  <aside data-theme="light">This panel is always light.</aside>
</html>
```

Brand colors (`--ab-color-brand-*`) stay the same in every Theme.

## Let the user choose

The app owns the choice and where it is stored:

1. Store the choice (System, Light or Dark) in a cookie.
2. Set `data-theme` for Light or Dark from a small inline script in `<head>`, before the page paints, and leave it off for System.
3. Declare `viewport.colorScheme = "light dark"`, so the browser paints the right background first.

Next.js describes this setup in [How to prevent flash before hydration](https://nextjs.org/docs/app/guides/preventing-flash-before-hydration).

## User settings

These follow the operating system on their own, with no code in the app:

| Setting              | What changes                                                       |
| -------------------- | ------------------------------------------------------------------ |
| Increased contrast   | Subtle borders, subtlest text and subtlest icons step up one level |
| Reduced transparency | Translucent materials become solid                                 |
| Reduced motion       | Movement stops; fades stay                                         |
| Forced colors        | Components redraw their edges in system colors                     |

## Custom tokens and themes

Themed tokens are `light-dark()` values that resolve on each element. If you register one of them with `@property` and `syntax: "<color>"`, it resolves once on `:root` and regions stop switching, so don't.
