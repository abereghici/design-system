# Getting started

Three steps: install the package, wrap the app in `UIProvider`, import components one at a time.

## Requirements

| Requirement     | Version                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| React           | <Peer name="react" />                                                                                                                     |
| Browser targets | [Baseline newly available](https://web.dev/baseline); nothing to polyfill, as the date components bring their own Temporal implementation |

## 1. Install

```sh
pnpm add @abereghici/ui
```

`@abereghici/tokens` comes with it. Then set the app's browser targets in `package.json`:

```json
{
  "browserslist": ["baseline newly available"]
}
```

Without this, Next.js lowers `light-dark()` for older browsers and `data-theme` regions stop switching.

## 2. Add the provider

Render `UIProvider` once, at the root. It brings the tokens, fonts and base styles, so the app imports no CSS from the design system.

```tsx
// app/layout.tsx
import type { Metadata } from "next";
import { UIProvider } from "@abereghici/ui/ui-provider";

export const metadata: Metadata = { other: { "text-scale": "scale" } };

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en-US">
      <body>
        <UIProvider locale="en-US">{children}</UIProvider>
      </body>
    </html>
  );
}
```

Give `locale` the same value as `<html lang>`, so dates and numbers match between server and browser.

The `text-scale` meta tag (`<meta name="text-scale" content="scale">` outside Next.js) lets the page follow the text size set in the operating system, in Chrome and Edge 146 and later. Components size text in `rem` and the design system never sets a root font size, so they scale with it. Don't set one yourself either.

## 3. Use a component

Each component has its own entry point. Importing one brings its own code, CSS and tokens, and those of the components it uses.

```tsx
import { Button } from "@abereghici/ui/button";
import { PlusIcon } from "@abereghici/ui/icons/plus";

<Button variant="primary">
  <PlusIcon />
  New project
</Button>;
```

Compound components are namespaces: `import { Card } from "@abereghici/ui/card"`, then `<Card.Root>` and `<Card.Title>`.

## Next.js

- **Server Components.** Static components render on the server; interactive ones are client components and need no `"use client"` from you.
- **CSS per route.** Next.js merges small stylesheets into shared chunks, so a route can load CSS for components it never imports. For strictly per-route CSS, set `cssChunking: { type: "graph", requestCost: 0 }` ([docs](https://nextjs.org/docs/app/api-reference/config/next-config-js/cssChunking)), at the cost of more requests.

## Before hydration

A server-rendered page is on screen before its JavaScript loads and hydrates it. Each component's description says, in one line, which of two tiers it belongs to:

- **Tier 1 works before hydration**, from the server HTML alone: links navigate, native fields submit with their form, Accordion and Disclosure sections open and close, and Dialog, AlertDialog, Sheet, Popover and ContextualHelp open and close. It works the same with JavaScript off.
- **Tier 2 shows its final content before hydration and works after it**: Tabs, Combobox, Command, the menus, Tooltip, Toolbar's arrow keys, NumberField, PasswordField's reveal button, SearchField's clear button, DateField, DatePicker, Calendar, RangeCalendar, DateRangePicker, TimeField, Tree, Splitter, CopyButton, Table selection, TagGroup's remove buttons, ToggleButton, ToggleButtonGroup, DropZone and toasts. They render on the server as they will look, so nothing moves when the page hydrates. Until then, a single-choice Combobox submits its typed text and NumberField its starting value. With JavaScript off, the controls only script can run are hidden, such as NumberField's step buttons and every tab but the selected one, and DateField, DatePicker, DateRangePicker and TimeField show the browser's own date or time inputs.

Build a page's main task from Tier 1 components, so it works while the rest of the page loads.
