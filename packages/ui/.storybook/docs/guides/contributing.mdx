# Contributing

## Tokens

Tokens are DTCG JSON in `packages/tokens/src/tokens/`, one file per tier, compiled by Style Dictionary into the `--ab-*` CSS. The full authoring guide is `packages/tokens/README.md`. Before a change:

1. Use only Dictionary words (see [Tokens](?path=/docs/foundations-tokens--docs)). A new word goes into `packages/tokens/src/naming.ts` in the same change.
2. Reference only the tier directly below.
3. Give every themed color a light and a dark value.
4. Run `pnpm --filter @platform/tokens build`. It fails on any broken rule and on any allowed color pairing below AA, and lists every problem at once.

## Components

Each component starts as a spec in `packages/ui/specs/<name>.md` (anatomy, states, keyboard, accessibility), then a folder in `packages/ui/src/<name>/` with the component, its CSS Module and its stories. Stories double as tests: every story renders in Chromium, with and without reduced motion, with an accessibility check, and the screenshot projects compare it in light, dark and right-to-left. Chromium also matches each story's accessibility tree against the aria snapshot committed in its component's `__snapshots__/` folder; after an intended change, review and rewrite them with `pnpm --filter @platform/ui test -u`. A component's docs page is generated from its TSDoc and its stories; the spec stays the internal design record.

## Releases

| Change                                                                  | Release |
| ----------------------------------------------------------------------- | ------- |
| Remove or rename a token or a prop; a value change that breaks contrast | Major   |
| Add a token, a Dictionary word, a component or a prop                   | Minor   |
| Adjust a value within its contract                                      | Patch   |

A deprecated token stays for one minor release as an alias of its replacement, and is removed in the next major.
