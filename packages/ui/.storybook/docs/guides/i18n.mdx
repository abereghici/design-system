# Internationalization

The library ships no interface text. Every label, button name and message is yours, so your app's wording and translation pipeline stay in your hands. Numbers and dates are formatted by `Intl` in the language you give the UIProvider.

## Write the text

Pass text as `children` or as a named prop. Where a part would otherwise have no accessible name (an icon-only Close, the step and navigation buttons, a landmark, a live status), TypeScript requires the text, so a nameless control is a type error:

```tsx
<Dialog.Close aria-label={t("close")} />
<NumberField label={t("seats")} incrementLabel={t("increase")} decrementLabel={t("decrease")} />
<Toaster aria-label={t("notifications")} closeLabel={t("dismiss")} />
<Spinner>{t("loading")}</Spinner>
```

## Set the language once

Give `UIProvider` the same BCP 47 tag as `<html lang>`. Every component that formats follows it: month and weekday names, date segments, percentages, grouped numbers and typed-text matching all come from `Intl` in that language. The server and the browser then format alike, so hydration matches; without it, each uses its own default language and the text can differ.

```tsx
// app/[lang]/layout.tsx
import { getDirection } from "@abereghici/ui/direction";
import { UIProvider } from "@abereghici/ui/ui-provider";

export default async function RootLayout({ children, params }: LayoutProps<"/[lang]">) {
  const { lang } = await params;

  return (
    <html lang={lang} dir={getDirection(lang)}>
      <body>
        <UIProvider locale={lang}>{children}</UIProvider>
      </body>
    </html>
  );
}
```

Dates are Gregorian in every language, so a locale whose default calendar differs (`th-TH`) shows the same year in a DateField and its Calendar.

## Direction

Right-to-left languages also need `dir` on `<html>`, as above. `getDirection` from `@abereghici/ui/direction` reads it from the tag and is safe on the server. See [Right-to-left](?path=/docs/guides-right-to-left--docs).
