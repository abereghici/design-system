# Internationalization

The library ships no interface text. Every label, button name and message is yours, so your app's wording and translation pipeline stay in your hands. Numbers and dates are formatted by `Intl` in the language you pass.

## Write the text

Pass text as `children` or as a named prop. Where a part would otherwise have no accessible name (an icon-only Close, the step and navigation buttons, a landmark, a live status), TypeScript requires the text, so a nameless control is a type error:

```tsx
<Dialog.Close aria-label={t("close")} />
<NumberField label={t("seats")} incrementLabel={t("increase")} decrementLabel={t("decrease")} />
<Toaster aria-label={t("notifications")} closeLabel={t("dismiss")} />
<Spinner>{t("loading")}</Spinner>
```

## Formatting

Components that format numbers or dates (Badge, Calendar, Combobox and Command matching, DateField, DatePicker, Meter, NumberField, Pagination, Progress, Slider) take an optional `locale`, a BCP 47 tag such as `"ro-RO"`, which they pass to `Intl`. Month and weekday names, date segment names, percentages and grouped numbers all come from `Intl`. Without `locale`, `Intl` uses the runtime's default language, which can differ between your server and the browser, so a server-rendered app passes the same `locale` everywhere:

```tsx
<Meter value={42} label="Spațiu" locale="ro-RO" />
```

## Migrate from locale objects

The `enUS` and `roRO` objects, the `@platform/ui/locales/*` entries, UIProvider's `locale` prop and every `labels` prop are gone. Move each string to the component that shows it, and pass the tag as `locale` where a component formats:

```tsx
// Before
<UIProvider locale={roRO}>
  <Dialog.Close labels={{ close: "Închide" }} />
  <Pagination page={2} count={9} getPageUrl={url} />
</UIProvider>

// After
<UIProvider>
  <Dialog.Close aria-label="Închide" />
  <Pagination
    page={2}
    count={9}
    getPageUrl={url}
    locale="ro-RO"
    aria-label="Paginare"
    previousLabel="Pagina anterioară"
    nextLabel="Pagina următoare"
  />
</UIProvider>
```

## Direction

Right-to-left languages also need `dir` on `<html>`. `getDirection` from `@platform/ui/direction` reads it from the tag and is safe on the server:

```tsx
import { getDirection } from "@platform/ui/direction";

<html lang={tag} dir={getDirection(tag)}>
```
