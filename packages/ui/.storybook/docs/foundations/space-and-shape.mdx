# Space and shape

Controls are the same size with a mouse and on a touch screen, so a layout never changes between the two.

## Space

Pick the kind of space first, then the size.

| Kind      | Use for                          | Example                    |
| --------- | -------------------------------- | -------------------------- |
| `inline`  | Gaps between items in a row      | Icon and label in a button |
| `inset`   | Padding inside a container       | Card padding               |
| `stack`   | Gaps between items in a column   | Fields in a form           |
| `section` | Separation between page sections | Blocks of a landing page   |

<SpaceScale />

Below <Value of="breakpoint-md" /> wide, `space-section` and `layout-gutter` shrink. In a media query, `em` is the browser's default text size, so readers with larger text get the narrow layout on wider screens.

## Size

Controls share four heights, so a button, a field and a select line up in a row. On a touch screen, a Button, IconButton or ToggleButton also takes presses in an invisible area above and below itself, up to <Value of="size-target-recommended" /> tall, so buttons side by side never take each other's presses.

| Control height | Value                          |
| -------------- | ------------------------------ |
| `xs`           | <Value of="size-control-xs" /> |
| `sm`           | <Value of="size-control-sm" /> |
| `md`           | <Value of="size-control-md" /> |
| `lg`           | <Value of="size-control-lg" /> |

## Density

Comfortable is the default. For a dense screen, set `data-density="compact"` on any element, and the buttons, icon buttons, toggle buttons, segmented controls and single-line fields inside it take the compact heights, as do the options of a Select, Combobox or Command, the items of a menu or Tree, the Tabs and the Steps of a Stepper, while a Table's rows get shorter; `data-density="comfortable"` goes back inside a compact region. The nearest setting wins.

| Control height | Comfortable                    | Compact                                |
| -------------- | ------------------------------ | -------------------------------------- |
| `sm`           | <Value of="size-control-sm" /> | <Value of="size-control-compact-sm" /> |
| `md`           | <Value of="size-control-md" /> | <Value of="size-control-compact-md" /> |
| `lg`           | <Value of="size-control-lg" /> | <Value of="size-control-compact-lg" /> |

<Canvas of={UIProviderStories.Density} />

Your own components can follow the density too, with a container style query: `@container style(--ab-density: compact) { … }`.

## Radius

Nested corners share a centre: the inner radius is the outer radius minus the padding between them.

<RadiusScale />

<Guidance>
<Do>

- Use `space-inset-*` for padding and `space-stack-*` or `space-inline-*` for gaps.
- Match the inner radius to the outer radius minus the padding.
- Use logical properties (`padding-inline`, `margin-block`), so layouts mirror in right-to-left.

</Do>
<Dont>

- Use `dimension-*` primitives for spacing.
- Give touch screens their own component variant; Buttons, IconButtons and ToggleButtons already take presses up to a comfortable height there.
- Read a custom property in a media query; CSS can't. Write the breakpoint's value.

</Dont>
</Guidance>
