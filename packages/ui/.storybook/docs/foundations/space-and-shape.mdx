# Space and shape

Compact with a mouse, comfortable on touch: the same tokens grow on touch screens, so no component needs a touch variant.

## Space

Pick the kind of space first, then the size.

| Kind      | Use for                          | Example                    |
| --------- | -------------------------------- | -------------------------- |
| `inline`  | Gaps between items in a row      | Icon and label in a button |
| `inset`   | Padding inside a container       | Card padding               |
| `stack`   | Gaps between items in a column   | Fields in a form           |
| `section` | Separation between page sections | Blocks of a landing page   |

<SpaceScale />

On narrow windows (below 760px), `space-section` and the layout gutter shrink.

## Size

Controls share four heights, so a button, a field and a select line up in a row. On touch screens every control height grows to a comfortable target.

| Control height | Mouse | Touch |
| -------------- | ----- | ----- |
| `xs`           | 24px  | 32px  |
| `sm`           | 28px  | 40px  |
| `md`           | 32px  | 44px  |
| `lg`           | 40px  | 48px  |

## Radius

Nested corners share a centre: the inner radius is the outer radius minus the padding between them.

<RadiusScale />

<Guidance>
<Do>

- Use `space-inset-*` for padding and `space-stack-*` or `space-inline-*` for gaps.
- Match the inner radius to the outer radius minus the padding.
- Use logical properties (`padding-inline`, `margin-block`), so layouts mirror in right-to-left.

</Do>
<Dont>

- Use `dimension-*` primitives for spacing.
- Give touch screens their own component variant; the tokens already grow.
- Read a custom property in a media query; CSS can't. Write the breakpoint's value.

</Dont>
</Guidance>

Lines, strokes and the layout widths are in the [token explorer](?path=/docs/reference-tokens--docs) under Shape and Layout.
