# Typography

Noto Serif for headings and statements, Figtree for everything people read and operate, and the system monospace for code.

## Choosing a role

| Role       | Typeface    | Use for                                         |
| ---------- | ----------- | ----------------------------------------------- |
| `heading`  | Noto Serif  | Page and section titles                         |
| `display`  | Noto Serif  | A short statement that opens a page             |
| `body`     | Figtree     | Paragraphs and descriptions                     |
| `label`    | Figtree     | Buttons, inputs, menus, tabs and other controls |
| `data`     | Figtree     | Numbers in tables and stats (tabular figures)   |
| `overline` | Figtree     | A small uppercase label above a group           |
| `kbd`      | Figtree     | Keyboard shortcut hints                         |
| `code`     | System mono | Code                                            |

## Scale

<TypeScale />

Sizes are in `rem`, so text follows the reader's default size. The larger steps also grow a little with the window.

## Applying a role

A role is two declarations, because the `font` shorthand can't carry letter spacing:

```css
.intro {
  font: var(--ab-type-body-lg);
  letter-spacing: var(--ab-type-body-lg-letter-spacing);
}
```

In React, use `Heading` and `Text`, which apply both.

<Guidance>
<Do>

- Use one `h1` per page, and keep heading levels in order.
- Keep reading text within `--ab-layout-column-width`.
- Use `data` for numbers that line up in columns.

</Do>
<Dont>

- Pick a heading level for its size; `Heading` takes `size` separately.
- Set `font-size` or `line-height` on their own; they drift from the role.

</Dont>
</Guidance>

## Fonts

`UIProvider` loads both families and preloads Figtree's latin file, the one almost every page needs. A browser downloads another file only when the page uses one of its characters or its italic. Both families are under the SIL Open Font License 1.1.
