# Color

Surfaces stay neutral. Color marks an action, a state, or the one highlight on a page. Light and dark each have their own neutral palette, Sage and Night.

## Surfaces

Three surfaces nest in the page, each on the one before it. Overlays float above the page and cast a shadow.

## Roles

Pick the token by the property you are setting (`background`, `text`, `icon`, `border`), then the role.

| Role        | Use for                              | Example tokens                                  |
| ----------- | ------------------------------------ | ----------------------------------------------- |
| Neutral     | Most text, icons and borders         | `text-default`, `text-subtle`, `border-default` |
| `accent`    | The primary action, checked controls | `background-accent-bold`, `text-accent`         |
| `selected`  | The current item in a set            | `background-selected`, `text-selected`          |
| `success`   | Completed, valid, positive           | `background-success-subtle`, `text-success`     |
| `warning`   | Needs attention, may cause problems  | `background-warning-subtle`, `text-warning`     |
| `danger`    | Errors, destructive actions          | `background-danger-bold`, `border-danger`       |
| `highlight` | Selected text                        | `background-highlight`, `text-on-highlight`     |

## Pairing text with fills

<FillPairs />

The token build checks every one of these pairs and fails if one drops below WCAG AA in either Theme. [Accessibility](?path=/docs/foundations-accessibility--docs) lists the measured contrast.

<Guidance>
<Do>

- Keep to one primary button per view.
- Pair a status color with a label or an icon.
- Use `border-default` for any edge a control needs to be seen.

</Do>
<Dont>

- Use a palette step (`--ab-palette-*`) in product code.
- Use a text token as a fill, or a fill as text.
- Use brand colors (`color-brand-*`) for interface roles; they are for brand imagery and print.

</Dont>
</Guidance>
