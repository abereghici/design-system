# Toast

A brief, non-blocking confirmation of something the user just did: "Link copied", "Moved to Archive · Undo". It appears at the bottom of the viewport, announces itself without taking focus, and leaves on its own. Errors that need action belong inline (Alert, Field errors), not in a toast; a decision that must interrupt is an AlertDialog. A toast is never the only place information or an action lives. Toasts are shown with the `toast()` function and drawn by the Toaster, which an app mounts once near its root (see `toaster.md`).

```tsx
import { toast } from "@platform/ui/toast";

toast({ title: "Link copied" });

const id = toast({
  title: "Moved to Archive",
  action: { label: "Undo", shortcut: "mod+z", onClick: restore },
});

toast({ title: "Couldn't sync", description: "Retrying in 30 seconds.", variant: "danger" });

toast.dismiss(id);
```

Status: draft for brand-owner review (phase 5). Source guide: `components/Toast/README.md` in the artifact (it also holds the Toaster's behaviour; `toaster.md` specifies the region, the stack and the announcements).

## Anatomy

Surface → status icon → Title + Description → Action → Dismiss.

- **Surface.** An `<li>` inside the Toaster's list, laid out as a grid: icon column, text column, actions column. Radius `toast-border-radius` (12), padding `toast-padding` (12), `toast-gap` (12) between columns, `toast-background-color` (`color-surface-floating`, solid: no Material) and `toast-shadow` (`elevation-toast`). Inline size `toast-width` (320), never wider than the viewport minus `space-inset-lg` on each side. Source: "Surface (radius 12, toast elevation) → status glyph → title (13/500) + description → inline action → dismiss."
- **Status icon.** Drawn from `variant`, decorative (`aria-hidden`), `toast-icon-size` (16), in the first row: `info` for neutral, `check-circle` for success, `warning` for warning, `danger` for danger, coloured `toast-{variant}-icon-color` (the same glyphs as Alert; the info and warning glyphs carry the bob diamond, the one motif on this surface).
- **Title.** A `<div>` in `toast-title-font` (`type-label-sm`, the source's 13/500) and `toast-title-text-color`. It wraps (the prototype truncates it to one line; judgement call: a truncated title hides the outcome, and ro-RO strings run longer).
- **Description** (optional). A `<div>` in the second row, spanning the text and actions columns, `toast-body-gap` (4) below the Title, in `toast-description-font` / `toast-description-text-color`.
- **Action** (at most one). A native `<button type="button">` in the actions column: "a text command in default ink (13/500, 24 tall, radius 5) with no border or shadow — a raised button on a floating surface reads as a second card. Fill appears only on hover/press." (source). Height `toast-action-height`, `toast-action-padding-inline`, `toast-action-border-radius`, `toast-action-font`, `toast-action-text-color`; fills `toast-action-background-color-hovered` / `-pressed`. With a `shortcut`, it ends with `<Kbd keys={shortcut} aria-hidden />` drawn flat (no keycap fill or border) in `toast-action-shortcut-text-color`, `toast-action-gap` from the label (source: "An optional shortcut hint sits inside it in subtlest ink."; the DropdownMenu Item precedent).
- **Dismiss.** A native `<button type="button">` with the `x` icon (`toast-icon-size`, `toast-close-icon-color`, `toast-close-icon-color-hovered` on hover), square at `toast-action-height`, radius `toast-action-border-radius`, the Action's hover and press fills, named by `labels.close` ("Dismiss"). It is drawn by the toast, not composed from IconButton, so one press dispatches one feedback event (Dialog Close precedent). Source: "**Dismiss** recedes until the toast is hovered or focused on fine pointers; always visible on touch; always focusable."

There is no Toast component in the public API: product code calls `toast()`, and the Toaster renders each toast (the prototype's static `Toast` export was "for documentation and previews"; the docs page renders toasts through `toast()` instead).

## API

`@platform/ui/toast` is a plain module (no `'use client'`, no React UI, no module-level side effects): `toast`, `toast.dismiss`, and the types `ToastOptions`, `ToastVariant`. Importing it never pulls the Toaster's code.

`toast(options: ToastOptions): string` adds a toast and returns its id. On the server (`typeof document === "undefined"`) it does nothing and returns `""`, so a module-level store never collects toasts across requests (the prototype's `if (!W) return`).

`toast.dismiss(id: string): void` closes that toast as if it timed out (no feedback event). An unknown or already closed id does nothing.

`ToastOptions`

| Option        | Type                                                        | Default     | Notes                                                                                                                                                                   |
| ------------- | ----------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`       | `string`                                                    |             | Required. Names the outcome ("Moved to Archive", not "Success").                                                                                                        |
| `description` | `string`                                                    |             | One short sentence.                                                                                                                                                     |
| `variant`     | `"neutral" \| "success" \| "warning" \| "danger"`           | `"neutral"` | Exposed as `data-variant`. Sets the icon, the duration and the announcement (danger is assertive).                                                                      |
| `action`      | `{ label: string; shortcut?: string; onClick: () => void }` |             | At most one. `onClick` runs, then the toast closes. `shortcut` uses Kbd's `keys` grammar (`"mod+z"`): shown in the Action and bound by the Toaster (Behaviour).         |
| `duration`    | `number`                                                    | token       | Milliseconds before it closes; `Infinity` keeps it until dismissed. Without it: `toast-duration` (4 s), or `toast-danger-duration` (6 s) for danger (Behaviour, Timer). |

Strings only, not `ReactNode` (judgement call: the announcement is the title and description text, and a toast holds no links or markup; Base UI and Sonner accept nodes).

Names, checked against the reference libraries:

- **`toast()`**: Sonner "Add `<Toaster />` to your app, it will be the place where all your toasts will be rendered. The source and Sonner agree on a callable `toast()`, and there is one Toaster, so no manager object is needed. Like Base UI's `add`, it returns the id.
- **`toast.dismiss(id)`**: Sonner's `toast` object has "`dismiss: ToastState.dismiss`" (`src/state.ts`) and its author's skill documents "`toast.dismiss(id?)` | Dismiss one toast, or all when called without an id." The id is required: dismiss-all has no need yet.
- **`title` / `description`**: Base UI "`title?: React.ReactNode;`" and "`description?: React.ReactNode;`"; Radix Toast Parts "Title: An optional title for the toast." and "Description: The toast message." (https://www.radix-ui.com/primitives/docs/components/toast); Ark `title`, `description`; Sonner `description`. Title is required here because the source's every example has one and the Title carries the outcome.
- **`variant`**: the source's word (`variant: 'danger'`) and the Alert precedent with the same Role values (`neutral · success · warning · danger`, matching the ported `toast-{variant}-icon-color` tokens). Base UI and Ark call it `type` (Base UI "The type of the toast. Used to conditionally style the toast, including conditionally rendering elements based on the type."); Sonner uses methods (`toast.success`, `toast.error`, `toast.warning`); Mantine `color`. One axis, so the Glossary's Variant.
- **`action`**: the source's `{ label, shortcut, onClick }`; Sonner "Action: Renders a primary button, clicking it will close the toast and run the callback passed via onClick." (https://sonner.emilkowal.ski/toast); Base UI "When adding a toast, the `actionProps` option can be used to define props for an action button inside of it—this enables the ability to undo an action associated with the toast."; Radix `Toast.Action` "An action that is safe to ignore to ensure users are not expected to complete tasks with unexpected side effects as a result of a time limit."
- **`duration`**: Sonner "duration number 4000"; Radix Root and Provider `duration` (Provider default 5000); Ark "duration … The duration of the toast. By default, it is determined by the type of the toast." and "use Infinity to keep it visible until manually dismissed"; the prototype's `Toast.d.ts` "ms; default 4000, danger 6000. Infinity to persist." Base UI and React Aria say `timeout` ("A value of `0` will prevent the toast from being dismissed automatically."), Mantine `autoClose`. Three libraries and the prototype say `duration`, with `Infinity`. Needed so a story can keep a toast on screen for its screenshot and so the app can keep a toast it will dismiss itself (judgement call: the source guide lists only the two defaults).

| State                                | How it shows                                                                     | Exposed as                            |
| ------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------- |
| neutral / success / warning / danger | The Variant's glyph and icon colour; same surface                                | `data-variant`                        |

| exiting                              | Fades and drops (or leaves in the swipe direction)                               | `data-exiting`                        |
| Action / Dismiss states              | Hover and press fills, focus ring                                                | `:hover`, `:active`, `:focus-visible` |

## Behaviour

- **One store, two modules.** `toast()` adds an entry to a module-level store in `src/toast/` (an array plus `subscribe`); the Toaster reads it with `useSyncExternalStore` (`toaster.md`). Toasts added before the Toaster mounts wait in the store and show when it mounts.
- **Timer.** Each toast closes after its duration. Script, not CSS: a `setTimeout` for the remaining time, where the duration comes from the `duration` option or, without it, from the token read on the toast element (`getComputedStyle(toast).getPropertyValue("--ab-toast-duration")`, or `--ab-toast-danger-duration` for danger, parsed as a CSS `<time>`), so an app that overrides the token in CSS changes the duration. Timers pause while the pointer is over the Toaster, while focus is inside it, and while the tab is hidden (source: "timers pause on hover, focus and hidden tabs"); each toast keeps its remaining time and resumes from there. `visibilitychange` gives the hidden state: MDN "The visibilitychange event is fired at the document when its visibility status changes — for example, when the user switches browser tabs…", read from `document.visibilityState`. Why not a CSS animation on the token with `animationend`: the hidden-tab pause needs script anyway, and the screenshot projects run with Vitest's `animations: 'disabled'`, which Playwright documents as "finite animations are fast-forwarded to completion" (docs/research/story-screenshots.md), so a CSS timer would close every toast before its screenshot. A script timer is not affected; stories that capture a toast pass `duration: Infinity`.
- **Durations and WCAG** (judgement call: the source's 4 s and 6 s stay, including for a toast with an Undo action). WCAG 2.2.1 Timing Adjustable: "For each time limit that is set by the content, at least one of the following is true: Turn off … Adjust … Extend …", but its Understanding document exempts a toast whose content is available elsewhere: "a web application such as an email client provides notification of new email arriving with a temporary message (such as a 'toast' message) … Users are able to identify the arrival of email through other means, such as viewing the Inbox, so the disappearance of the message does not set a time limit … If the user has no other means of discovering the same information (or performing the same function), then each message would need to meet this success criterion". So the documented rule is the source's "Never the only place critical information appears", extended to the Action: whatever Undo does must also be possible elsewhere (Radix: an Action is one "that is safe to ignore"). WCAG 2.2.2 Pause, Stop, Hide counts content that "updates or disappears based on a preset time interval" as auto-updating and asks for "a mechanism for the user to pause, stop, or hide it"; the hover / focus pause, the always-focusable Dismiss and the Alt+T focus hotkey are those mechanisms (inference). React Aria advises "For accessibility, toasts should have a minimum timeout of 5 seconds." The 4 s default is below that: flagged for the brand owner.
- **Action.** Pressing it runs `onClick`, dispatches `ab-confirm`, then closes the toast (source: "it closes the toast and plays the confirm click"). No veto: Sonner's `event.preventDefault()` to keep the toast open has no need here.
- **Action shortcut.** The Toaster listens for `keydown` on `document`. When the newest toast has an action with a `shortcut`, a matching key press (`mod` = Meta on Apple platforms, Control elsewhere, as Kbd resolves it; the letter compared with `event.key`, case-insensitive) calls `click()` on that Action, so the click path, `onClick`, `ab-confirm` and the close are the same as a press (MDN: "The HTMLElement.click() method simulates a mouse click on an element."). It does nothing when the newest toast has no shortcut (an older toast's shortcut never fires), when the event is already `defaultPrevented`, or while focus is in a form control or editable content (`input`, `textarea`, `select`, or `isContentEditable`), so native undo is never hijacked (source: "Its shortcut (⌘Z / Ctrl Z) targets the newest toast only and is ignored while focus is in a text field"; the prototype's `isEditing` also counts `select`). A handled shortcut calls `preventDefault()`. The Action carries `aria-keyshortcuts` derived from the shortcut (`"Meta+Z"` on Apple, `"Control+Z"` elsewhere).
- **Dismiss.** The Dismiss button, Escape while focus is inside the toast, and a swipe close the toast and dispatch `ab-dismiss`. Escape calls `preventDefault()` on the `keydown`, so when the Toaster sits inside an open modal (`toaster.md`) the dialog does not also close (HTML close request steps: "If event is not null, and its canceled flag is set, then return."; phase-4 contract 8).
- **Swipe** (pointer only). `pointerdown` with the primary button on the surface, not on the Action or Dismiss (Sonner returns early for a `BUTTON` target; Base UI ignores "button,a,input,textarea,[role="button"]"), starts tracking and calls `setPointerCapture` (MDN: "designate a specific element as the capture target of future pointer events"). `pointermove` moves the toast with the pointer through `--swipe-x` / `--swipe-y` (runtime custom properties, the TextArea `--min-rows` precedent), sideways in either direction and only downwards (upward movement is clamped to 0, as the prototype does). On `pointerup` it closes when the distance is more than 45 px or the speed is more than 0.11 px/ms; otherwise it settles back (`pointercancel` always settles back). Source: "Swipe down/sideways (> 45px or fast flick) dismisses."; Sonner: "`const SWIPE_THRESHOLD = 45;`" and "`if (isAllowedDirection && (Math.abs(swipeAmount) >= SWIPE_THRESHOLD || velocity > 0.11))`" where "`const velocity = Math.abs(swipeAmount) / timeTaken;`" (`src/index.tsx`); Base UI uses 40 ("`const SWIPE_THRESHOLD = 40;`"), Radix Provider `swipeThreshold` "50". The surface has `touch-action: none` (MDN: "Disable browser handling of all panning and zooming gestures."), so a vertical swipe on touch never scrolls the page; the toast itself never scrolls. Keyboard users dismiss with Escape or Dismiss.
- **Exit.** A closing toast stays mounted with `data-exiting` until its exit transition ends (`Promise.all(element.getAnimations().map((a) => a.finished))`, which resolves at once when nothing runs, e.g. with transitions off), then leaves the store. It is no longer counted in the stack, so the toasts behind move forward at once.
- **Server Components.** None: every Part of a toast is rendered by the `'use client'` Toaster. `@platform/ui/toast` has no directive because it renders nothing.

## Motion

Source: "Enters from below on `spring-gentle` (500ms); older toasts tuck behind (−8px, −5% scale per step, max 3 visible). Hover or focus fans the stack out. Exit 150ms ease-out." The stack geometry is the Toaster's (`toaster.md`).

- **Enter:** `@starting-style { opacity: 0; translate: 0 100%; }` to its stack position over `toast-enter-duration` with `toast-enter-easing` (`motion-easing-spring-gentle`, a `linear()` spring). Brand book: "**Springs.** Only where the user directly causes the movement: switch thumbs, segmented and tab indicators, the radio diamond, toast entrance." The spring's overshoot (the curve peaks at 1.0158) clamps harmlessly on `opacity` (inference). `toast-enter-duration` is ported as `motion-duration-spring` (400 ms), but the source and spec #1 story 61 say 500 ms, which is `motion-duration-spring-gentle`: the token should be retargeted (flagged).
- **No keyboard gate.** A toast is not opened by the user's key press or pointer, so the `data-pointer` gate does not apply; it is not high-frequency either (brand book "No motion on keyboard-initiated or high-frequency (100+ per day) actions."). Every toast animates in.
- **Stack moves** (tuck, fan-out, settle after a swipe) transition `translate` and `scale` over `toast-stack-duration` (`motion-duration-expand`, 250 ms) with `toast-stack-easing` (`motion-easing-enter`, ease-out): the system initiates them, so they ease out (brand book "Everything the system initiates eases out."). Swiping has no transition: the toast follows the pointer 1:1.
- **Exit:** `opacity` to 0 and `translate` down by its own height over `toast-exit-duration` (`motion-duration-exit`, 150 ms) with `toast-exit-easing`: faster than the entry ("Exits are faster than entrances."). After a swipe it continues in the swipe direction from where it is.
- **Reduced motion:** the entry and exit only fade (the `translate` is dropped in `@media (prefers-reduced-motion: reduce)`), and the stack is always fanned out with no scale, so nothing moves or scales on hover (decision for contract 10; brand book "Reduced motion removes movement, scaling, blur and stagger. Opacity and color fades remain."; `toast-stack-scale` resolves to 1 through `motion-scale-enter-modal`'s media override). A swipe still follows the pointer: the user moves it directly (the Slider precedent).
- **Instant exit:** a toast is an `<li>` inside the Toaster, not a top-layer element of its own, so its exit is an ordinary transition that runs in every engine (inference; spike #4 measured top-layer exits only). Where transitions do not run (screenshot projects, a user agent with animations off) it disappears in one frame after the gesture or the timer that closed it; the toasts behind take its place and focus is never inside it unless the user put it there (Toaster, focus after dismiss), so nothing is left half-drawn.

## Keyboard

There is no APG pattern for toasts: the APG patterns index (https://www.w3.org/WAI/ARIA/apg/patterns/) lists Alert, Alert and Message Dialogs, Dialog (Modal), Landmarks and others, and no toast or notification pattern. The closest is **Alert** (https://www.w3.org/WAI/ARIA/apg/patterns/alert/): "Keyboard Interaction: Not applicable." and "it is crucial they do not affect keyboard focus". A toast never takes focus; its controls are APG **Buttons** (https://www.w3.org/WAI/ARIA/apg/patterns/button/). The keys below come from the source and the reference libraries; the Toaster's region keys (Alt+T, Escape on the region) are in `toaster.md`.

| Key                                      | Source                                                                                                                                                | Here                                                                                        |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Tab / Shift + Tab                        | Radix "Tab: Moves focus to the next focusable element." / "Shift + Tab: Moves focus to the previous focusable element."                               | Through each visible toast's Action and Dismiss, newest first.                              |
| Enter / Space (Action, Dismiss)          | APG Button "Enter: Activates the button." / "Space: Activates the button."; Radix "When focus is on a Toast.Action or Toast.Close, closes the toast." | Runs the action and closes, or dismisses.                                                   |
| Escape (focus inside a toast)            | Radix "Esc: When focus is on a Toast, closes the toast."; Base UI closes the toast on Escape when focus is inside it (`ToastRoot.tsx`)                | Dismisses that toast (`ab-dismiss`); `preventDefault()` so an enclosing modal stays open.   |
| The action's shortcut (e.g. ⌘Z / Ctrl+Z) | Source "targets the newest toast only and is ignored while focus is in a text field"                                                                  | Runs the newest toast's action from anywhere, except in a form control or editable content. |

**RTL:** no arrow-key behaviour, so nothing to swap. Swipe works in both inline directions.

## Accessibility

- **Announcement.** Every toast is announced politely and a danger toast assertively (spec #1 story 39), through the Toaster's always-mounted live regions, not a role on the toast itself (`toaster.md`, Announcements: MDN says an element inserted with its message already in it "generally does not lead to an announcement"). The announced text is the Title, then the Description. Departure from the source ("Toasts are `role="status"`, danger is `role="alert"`"): the roles move to the Toaster's announcers (judgement call). Satisfies WCAG 4.1.3 Status Messages: "status messages can be programmatically determined through role or properties such that they can be presented to the user by assistive technologies without receiving focus" (technique ARIA22 "Using role=status to present status messages").
- **No focus.** A toast never moves focus when it appears (APG Alert; ARIA 1.2 status: "Authors SHOULD ensure an element with role status does not receive focus as a result of change in status.").
- **Never the only place.** Documented rule, from the source and WCAG 2.2.1 (Behaviour): what a toast says and what its Action does are also available elsewhere in the app.
- **Shortcut.** The Kbd inside the Action is `aria-hidden` and the Action carries `aria-keyshortcuts` (Kbd contract), so its name stays "Undo". MDN: "The aria-keyshortcuts attribute exposes the existence of the shortcut to assistive technologies so the presence of the shortcut can be communicated to its users."
- **Icons** are decorative; the Title carries the outcome in words and the glyph shape is the second channel (brand book "State always pairs color with a label, a shape, a weight change or an underline.").
- **Dismiss** is always focusable, also while it is visually receded: under `@media (hover: hover) and (pointer: fine)` it has `opacity: 0` until the toast matches `:hover` or `:focus-within`, or the button matches `:focus-visible` (source). On touch it is always visible.
- **Targets:** Action and Dismiss are `toast-action-height` (`size-control-xs`, 24 px, which grows on coarse pointers), meeting WCAG 2.5.8's 24 px minimum.
- **Contrast.** Title and Action `color-text-default`, Description `color-text-subtle`, shortcut `color-text-subtlest`, icons `color-icon-{accent,success,warning,danger}` and `color-icon-subtlest` / `color-icon-default` on `color-surface-floating`, and the Action / Dismiss text and icons on `background-neutral-subtle-hovered` / `-pressed`: every pair is already in `contrast-matrix.ts`.
- **More contrast:** the Description takes `toast-title-text-color` and the surface draws a 1 px `color-border-default` border (`border-width-default`), so its edge no longer relies on the shadow (`@media (prefers-contrast: more)`, Dialog precedent); the shortcut steps up through the `text-subtlest` token override.
- **Forced colors:** the shadow disappears, so the surface draws a 1 px `CanvasText` border in `@media (forced-colors: active)`; icons use `currentColor`. The glyph shapes and the Title still tell the Variants apart.
- **Reduced transparency:** not affected (solid surface, no Material).

## RTL

Logical properties only: icon at the inline start, Action and Dismiss at the inline end, the Description spanning to the inline end. The Kbd keeps `dir="ltr"` (Kbd spec). The `x` and status glyphs are not directional and do not mirror. Swipe uses physical `clientX` deltas in both directions, so it needs no mirroring.

## Built-in labels

## Feedback events

| Event        | When                                                         | `reason`         |
| ------------ | ------------------------------------------------------------ | ---------------- |
| `ab-appear`  | A toast is first rendered                                    | `"programmatic"` |
| `ab-confirm` | Its Action runs (press or shortcut), after `onClick`         | `"user"`         |
| `ab-dismiss` | Dismiss pressed, Escape inside it, or a swipe that closes it | `"user"`         |

Detail: `{ component: "Toast", reason }`, dispatched from the toast's `<li>` (the Action or Dismiss button for presses), bubbling to `document` from wherever the Toaster is rendered. `ab-appear` is `"programmatic"` because the design system shows the toast without a gesture of the user's on it (docs/research/feedback-events-and-i18n.md: "Toasts and popovers that appear without a gesture rely on sticky activation for audio and vibration (MDN). Mark these with `reason: 'programmatic'` so apps can choose to stay silent."; source "Soft click on appear"). It fires once per toast, never again when the Toaster moves into a modal (`toaster.md`). A timeout and `toast.dismiss(id)` dispatch nothing. `src/events/events.ts`: add `"ab-appear": AppearEvent` (`CustomEvent<FeedbackEventDetail<"Toast">>`), and add or widen `"ab-confirm"` (AlertDialog) and `"ab-dismiss"` (Alert, Popover, Dialog, …) with `"Toast"`.
