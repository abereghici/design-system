# Combobox

Choose one value from a long or open-ended list by typing to narrow it: an assignee, a country, a repository. The value must be one of the Items; typed text only filters. For a short known list (up to about 15 options) use Select; for 2–6 options that should stay visible, RadioGroup; for free text with suggestions, a TextField; to run commands rather than choose a form value, Command.

```tsx
import { Combobox } from "@platform/ui/combobox";
import { UserIcon } from "@platform/ui/icons/user";

<Combobox.Root label="Assignee" name="assignee" placeholder="Search people" required>
  <Combobox.Item value="ab" keywords={["alex"]}>
    <UserIcon />
    Alexandru Bereghici
  </Combobox.Item>
  <Combobox.Item value="im">
    <UserIcon />
    Ioana Munteanu
  </Combobox.Item>
  <Combobox.Group label="Former members">
    <Combobox.Item value="eh" disabled>
      Erik Halvorsen
    </Combobox.Item>
  </Combobox.Group>
</Combobox.Root>

<Combobox.Root
  label="Repository"
  name="repository"
  filter={null}
  value={repository}
  onValueChange={setRepository}
  inputValue={query}
  onInputValueChange={setQuery}
>
  {results.map((result) => (
    <Combobox.Item key={result.id} value={result.id}>
      {result.fullName}
    </Combobox.Item>
  ))}
</Combobox.Root>
```

## Anatomy

Label → field box (search icon, input) → list (Floating layer: Groups, Items, empty row) → description or error. A hidden input carries the form value; a visually hidden status region announces "No results".

- **Label, description, error.** The Field Parts, built in (Field spec), as Select.
- **Field box.** TextField's container chrome (`input-*`: height 32 / 40, radius 8, hairline, raised elevation) holding a decorative `search` Icon at the inline start (TextField's start Icon, `input-icon-color`, `aria-hidden`) and the input, as the source's `<Combobox>` (`ab-input-group` + `search`; Q46-1). A pointer press anywhere on the box focuses the input and opens the list.
- **Input.** A native `<input type="text" role="combobox">` with no border or background of its own, `dir="auto"`, `autocomplete="off"` by default, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` → list id, and `aria-activedescendant` → the highlighted option while there is one. It has no `name`: its text is the query, not the value.
- **Hidden input.** `<input type="hidden" name form value>` holding the chosen Item's `value` (empty string when none).
- **List.** One `<div popover="manual" role="listbox" aria-labelledby={labelId}>`, rendered right after the field box (no portal) and shown in the top layer. Material `combobox-list-background-color` (`color-material-thick`) with `backdrop-filter: blur(combobox-list-blur) saturate(combobox-list-saturate)`, `combobox-list-shadow` (overlay elevation), radius `combobox-list-border-radius` (12), padding `combobox-list-padding` (4), `combobox-list-offset` (4) from the field box, at least as wide as it, at most `combobox-list-max-height` (320) tall, then scrolling (`overflow-y: auto`).
- **Item.** A `<div role="option" id>`, a flex row `combobox-option-height` (28), `combobox-option-padding-inline` (8), `combobox-option-gap` (8), radius `combobox-option-border-radius` (8: concentric, 12 − 4), `combobox-option-font`, `combobox-option-text-color`. Children, in order: an optional Icon (`combobox-option-icon-color`), the label, and a 16 px check box at the inline end (the `check` Icon in `combobox-option-icon-color-selected` on the chosen Item, empty otherwise), as the source's `.ab-option` > `.ab-indicator` (Q46-1). The whole row is the hit target.
- **Group.** A `<fieldset aria-labelledby>` (implicit role `group`, DropdownMenu precedent) whose first child is its label, a `<div role="presentation" id>` in the overline type (`type-overline-sm`, `color-text-subtlest`, as Select's group label), padded like an Item's text.
- **Empty row.** When no Item is shown, the list shows the built-in "No results" (`labels.noResults`) in `type-body-xs` / `color-text-subtle`, padded like an Item, `aria-hidden` (the status region announces it).
- **Status region.** A visually hidden `<output>` (implicit role `status`) inside the field root, always rendered, empty unless the list is open and empty.

## Behaviour

- **Field.** Follows the Field contract (`field.md`): label, description and error built in, `aria-describedby`, `:user-invalid` timing, server errors, reset. The visible input carries the constraint attributes: hidden inputs cannot (MDN: "Hidden inputs don't participate in constraint validation; they have no real value to be constrained."). That works because of one invariant: **while the list is closed, the input's text is the chosen Item's label, or empty when there is no value** (every close below restores it). So `required` on the visible input fails `valueMissing` exactly when no value is chosen, and the browser's own message and `:user-invalid` apply. While the list is open the user is mid-edit; submission cannot happen without a close first (Enter is taken while open, see Keyboard; a press on a submit button moves focus first). After each value change the Combobox re-runs the Field's validity read, as a `change` would. Reset restores `defaultValue` and its label.
- **Form value.** The hidden input submits the chosen Item's `value` under `name` (Base UI "`inputRef` … A ref to the hidden input element."; React Aria "Use the `name` prop to submit the `id` of the selected item to the server." and `formValue` default `'key'`). The typed text is never submitted. A Combobox with `aria-disabled` still submits its value (Field contract, step 7).
- **The list is a manual popover.** Source: "Listbox is a manual popover anchored to the input; flips above near the viewport edge." MDN popover: "manual popovers cannot be "light dismissed" and are not automatically closed." It opens with `showPopover({ source: fieldBox })`. The source is the field box, not the input: HTML show popover "Set element's implicit anchor element to source.", and the box is what the list lines up with and must be at least as wide as (the input is narrower: it sits between padding and the chevron). The source also becomes the list's popover trigger for focus navigation, which does not matter here because the list holds nothing focusable (inference). Showing a manual popover closes no other popover, so a Combobox inside an open Popover or DropdownMenu leaves it open, and a press inside the list counts as inside that Popover: HTML "nearest inclusive open popover" walks "currentNode's parent in the flat tree" and returns only popovers whose mode "is "auto" or "hint"", which skips the manual list and finds the enclosing Popover (inference from the algorithm; the build ticket checks a Combobox inside a Popover in three engines). Rendered in place, the list inherits `dir`, `lang` and theme (spike #4 §4) and the IDREFs of `aria-controls` and `aria-activedescendant` resolve in the same tree.
- **Opening** (`onOpenChange(true, details)`, `cancel()` skips the `showPopover()`):
  - typing that changes the text (`"input-change"`); the list stays open while there is text or not;
  - a pointer press on the field box, the input included (`"input-press"`; Base UI `openOnInputClick` default `true`); a press while open does nothing, so the caret can be placed;
  - Down or Up Arrow while closed (`"list-navigation"`).
    Focus stays on the input: the popover focusing steps focus a descendant only if it has the `autofocus` attribute (Popover spec), and no option does.
- **Query.** The query is what the user typed since the list opened. Opening without typing (press, arrow keys) shows every Item in document order, as React Aria does when its menu is opened by the button or arrows (inference from React Aria's behaviour; nothing in its docs says it). Typing sets the query to the trimmed input text.
- **Ranking** (one private module, `src/filter/`, no `index.ts`; Command uses it too). Source: "Fuzzy match (prefix > word start > subsequence)."
  1. An empty query shows every Item, in document order.
  2. Otherwise each Item gets the best tier over its label and each of its `keywords`: **prefix** (the string starts with the query) beats **word start** (a word of the string starts with the query) beats **subsequence** (the query's characters appear in the string in order, gaps allowed; a substring counts as one). An Item with no tier is hidden (`hidden` attribute, so it leaves the accessibility tree too).
  3. Matches are ordered by tier; within a tier, document order is kept: the order is computed with `Array.prototype.toSorted` (webstatus `array-by-copy`, widely available, low 2023-07-04), the copying version of `sort()` (MDN: "The toSorted() method of Array instances is the copying version of the sort() method."), and "Since version 10 (or ECMAScript 2019), the specification dictates that Array.prototype.sort is stable."
  4. Comparison is case- and accent-insensitive: `new Intl.Collator(locale, { usage: "search", sensitivity: "base" })`. MDN: `"search"` is "For filtering a list of strings by testing each list item for a full-string match against a key."; `"base"`: "Only strings that differ in base letters compare as unequal. Examples: a ≠ b, a = á, a = A."; and "Because the core functionality of "search" is accent-insensitive and case-insensitive filtering, setting it to "base" makes the most sense". A collator compares whole strings, so a prefix or word-start test compares the slice of the string that starts there and is as long as the query (`compare(slice, query) === 0`), and the subsequence test compares one grapheme at a time (`new Intl.Segmenter(locale)`, grapheme granularity, MDN: "Split the input into segments at grapheme cluster (user-perceived character) boundaries"). Both strings are normalised to NFC first so a decomposed "ș" and a precomposed one compare alike (inference: the build ticket checks "ș", "ţ" and "ä" queries against Romanian and German labels).
  5. Word starts come from `new Intl.Segmenter(locale, { granularity: "word" })` (MDN: "Split the input into segments at word boundaries, as determined by the locale."): the `index` of each segment whose `isWordLike` is true. So "Ioana Munteanu" matches "mu" at a word start and "Erik Halvorsen" matches "hv" as a subsequence.
  6. `locale` is the Root's `locale` prop (Base UI Combobox's), else the runtime's default; a Collator and two Segmenters are created once per locale and cached, lazily, never at import (the module has no side effects).
  7. The order is drawn, never applied to the DOM: the listbox and each Group are flex columns and each shown option gets `order` from its rank, so React's DOM is never reordered (cmdk reorders DOM nodes React owns and warns it "Uses risky approaches like manual DOM ordering"). MDN warns: "Using the order property will create a disconnect between the visual presentation of content and DOM order." Users reach options through the input (`aria-activedescendant` and the arrow keys follow the ranked order, not the DOM), and each shown option carries `aria-posinset` / `aria-setsize` within its parent so the spoken "n of m" matches the visible position (judgement call, shared with Command; inference that screen readers use them for options whose DOM order differs: the screen-reader pass checks it).
  8. Groups keep document order; Items rank within their Group; a Group with no shown Item is hidden. (cmdk also moves Groups by their best score; Command follows the source's "re-sorted within groups", and so does Combobox: judgement call.)
  9. `filter={null}` skips all of this: every rendered Item shows in the consumer's order.
- **Highlight.** The first enabled option in the shown order is highlighted whenever the shown options change and when the list opens (source: "First match is pre-highlighted so Enter always does something."; APG "List autocomplete with automatic selection: … the first suggestion is automatically highlighted as selected."). Opening without a query highlights the chosen Item when there is one. Down / Up move it to the next / previous enabled option, wrapping (APG list autocomplete example: "If visual focus is on the last option, moves visual focus to the first option."); disabled options are skipped (Mantine: "Selects next `Combobox.Option` that is not disabled."). The highlighted option is the input's `aria-activedescendant`, has `aria-selected="true"` and `data-highlighted`; after a keyboard move or a re-rank it is scrolled with `scrollIntoView({ block: "nearest" })` (MDN: "Scrolls as little as possible to bring the element into view. … If the element is already visible, no scrolling is done."; APG example: "When a keyboard event changes the active option in the listbox, the JavaScript scrolls the option referenced by aria-activedescendant into view."). Not after pointer moves, which would make the list jump. `scrollIntoView` could also scroll the page in some engine even though the list is in the top layer (inference; the build ticket checks the page does not move).
- **Highlight follows the pointer.** `pointermove` (mouse or pen) over an enabled option highlights it, with no transition (DropdownMenu precedent; Base UI `highlightItemOnHover` default `true`: "Whether moving the pointer over items should highlight them."). Moving off the options keeps the last highlight, so Enter still chooses something (judgement call: DropdownMenu clears it; here the source's "Enter always does something" wins). `mousedown` on the list calls `preventDefault()` so focus stays on the input (inference: focusing is the default action of `mousedown`; the build ticket checks focus after a click on an option in three engines).
- **Choosing** (`"item-press"`): a click on an enabled option, or Enter while an option is highlighted. In order: `onValueChange(value, details)` (`cancel()` keeps the old value, the list stays open and the text unchanged); the text becomes the Item's label with the caret at the end (Ark `selectionBehavior` `"replace"`: "The selected item string is set as the input value"; APG "placing the input cursor at the end of the accepted value"), `onInputValueChange(label, { reason: "item-press" })`; the list closes (`onOpenChange(false, { reason: "item-press" })`). Choosing the chosen Item again changes nothing and only closes. A disabled Item does nothing.
- **Closing without choosing** restores the invariant: the text goes back to the chosen label (or empty).
  - **Escape** while open (`"escape-key"`): closes and restores the text. APG: comboboxes let users "navigate the set of available choices in a combobox popup or menu and then press escape, which closes the popup or menu without changing previous input."
  - **Escape** while closed with a value or text (`"escape-key"`): clears both, `onValueChange(null)` and `onInputValueChange("")` (source "Esc close, then clear"; APG: "Optionally, if the popup is hidden before Escape is pressed, clears the combobox."; MUI `clearOnEscape`: "If true, clear all values when the user presses escape and the popup is closed."). Both Escape keydowns call `preventDefault()`, which stops the close request (HTML close request steps: "If event is not null, and its canceled flag is set, then return."), so an enclosing Dialog, Sheet or Popover stays open (phase-4 contract 8). A third Escape on an empty, closed Combobox is left alone and closes the enclosing layer.
  - **Focus leaving the field** (`"focus-out"`: Tab, Shift+Tab, a click on another control): source "Tab leaves without choosing." A `focusout` on the input whose `relatedTarget` is outside the field root closes the list and restores the text, without choosing the highlighted option. This departs from APG's automatic selection ("The automatically selected suggestion becomes the value of the combobox when the combobox loses focus unless the user chooses a different suggestion"), as MUI (`autoSelect` default `false`) and Mantine (`autoSelectOnBlur` opt-in: "Set the autoSelectOnBlur prop to automatically select the highlighted option when the input loses focus.") also default; the source decided. Restoring the text is React Aria's default ("By default, the value will be reverted to the selected item on blur."); MUI `clearOnBlur` clears instead ("the input's text is cleared on blur if no value is selected"). A `null` `relatedTarget` with `document.hasFocus()` false (switching windows) changes nothing (inference). The restore runs in the input's own `focusout` listener, before the Field reads `:user-invalid`, so an empty required Combobox shows its error on leaving (inference; the build ticket checks the error appears after Tab with no choice).
  - **A press outside** the field root and the list (`"outside-press"`): a `pointerdown` on `document` closes and restores, as light dismiss would for an auto popover.
  - **Emptying the input** by editing (`"input-clear"`): clears the value at once (`onValueChange(null)`), as MUI and React Aria do; the list stays open showing every Item.
  - All closes are the Combobox's own script, so `cancel()` keeps the list open for every reason (unlike auto popovers, whose light dismiss cannot be vetoed).
- **Nothing matches.** The list stays open with the "No results" row; Enter does nothing (it still calls `preventDefault()`, so the form is not submitted with a half-typed query).
- **One state path.** Controlled `open`, `value` and `inputValue` are applied in layout effects; a parent that refuses a change keeps its values (Popover precedent). A controlled `open` change calls no callback, reason `"none"` when reported.
- **Server rendering.** Item labels are read from the rendered Items, so on the server and before hydration the input shows `defaultInputValue` (or nothing). A server-rendered form with a preset value passes both `defaultValue` and `defaultInputValue` (judgement call: the alternative is a data `items` prop, left out).
- **Disabled** (`aria-disabled`): the input is `readOnly`; presses, arrows and Escape do nothing; the value still submits. Inside a disabled Fieldset the input is natively disabled and the hidden input is not submitted (native).
- Client components (`'use client'`): Root (state, Field, popover, listeners), Item (registers with the Root, reads its highlight and rank), Group (label id, hides when empty).

## Motion

Same Floating-layer motion as Select's picker and the menus (Menu source: "Scales from .97 at its trigger corner + fades, 200ms in / 150ms out (ease-out). Highlight follows the pointer instantly — no transition on hover inside menus.").

- **Pointer opens** (`data-pointer`, set on the field box's `pointerdown`, cleared on `keydown`, the Accordion rule): `opacity` 0 → 1 and scale from `combobox-list-enter-scale` (`motion-scale-enter`, 0.97) over `combobox-list-enter-duration` (`motion-duration-popover`, 200 ms), `combobox-list-easing` (`motion-easing-enter`), with `@starting-style`, `transform-origin` at the field box's block-start inline-start corner (mirrored with `:dir(rtl)`). Brand book: "Popovers and tooltips grow from their trigger".
- **Keyboard opens** (typing, arrow keys): no transition at all. Typing opens the list many times a day (brand book: "No motion on keyboard-initiated or high-frequency (100+ per day) actions."), and a fade on each keystroke would delay the results.
- **Re-ranking and highlight:** no motion; the order and the fill change in one frame.
- **Exit:** after a pointer choice, `opacity` over `combobox-list-exit-duration` (`motion-duration-exit`, 150 ms) with `display` and `overlay` `allow-discrete`, no scale; keyboard closes are instant.
- **Reduced motion:** `motion-scale-enter` resolves to 1 (token media override), so pointer opens only fade.
- **Instant exit:** spike #4: "Firefox and WebKit compute `display: none` at once". The list closes when the user chose, pressed Escape, or left the field; the input already shows the chosen label and focus is where the user put it, so a list that disappears in that frame reads as correct.

## Accessibility

- **Roles.** ARIA in HTML allows `input type=text` the role "combobox". APG: "The element that serves as an input and displays the combobox value has role combobox."; "The combobox element has aria-controls set to a value that refers to the element that serves as the popup. Note that aria-controls only needs to be set when the popup is visible. However, it is valid to reference an element that is not visible." (always set here); "When the popup element is visible, aria-expanded is set to true."; `aria-autocomplete="list"`: "When the popup is triggered, it presents suggested values. If the combobox is editable, the values complete or logically correspond to the characters typed in the combobox." No `aria-haspopup`: "elements with role combobox have an implicit aria-haspopup value of listbox."
- **Active descendant.** APG: "When a descendant of a listbox, grid, or tree popup is focused, DOM focus remains on the combobox and the combobox has aria-activedescendant set to a value that refers to the focused element within the popup." MDN: "The value of aria-activedescendant refers to an owned element of the controlled element. For example, in a combobox, focus may remain on the combobox while the value of aria-activedescendant on the combobox element refers to a descendant of a popup listbox that is controlled by the combobox." It is removed while nothing is highlighted (list closed, or empty).
- **Selected = highlighted.** APG: "For a combobox that controls a listbox, grid, or tree popup, when a suggested value is visually indicated as the currently selected value, the option, gridcell, row, or treeitem containing that value has aria-selected set to true." APG example: `aria-selected="true"` is "Specified on an option in the listbox when it is visually highlighted as selected. Occurs only when an option in the list is referenced by aria-activedescendant." Other enabled options carry `aria-selected="false"`; disabled ones `aria-disabled="true"` with it (MDN option: "A disabled option can have aria-disabled="true" and aria-selected="false" to communicate to the user that the option is present, albeit disabled."). The chosen Item's check is decorative; the input's text is the value AT reads.
- **Names.** The input from `<label for>` (APG: "it is labeled using the label element"); the listbox through `aria-labelledby` → the same label (the APG example names its listbox, `aria-label="States"`); Groups through their label (a `role="presentation"` label element, so the group holds only options in the accessibility tree: inference from WAI-ARIA's "group with accessibility child option"; the screen-reader pass records the group name being read). Options take their name from their text; decorative Icons are `aria-hidden`.
- **Required and value.** Native `required` on the input; APG: "Comboboxes and listboxes can be marked as required with aria-required="true", and they have an accessible name that is distinct from their value." The hidden input is not in the accessibility tree.
- **"No results".** Announced through the always-rendered `role="status"` region: MDN live regions: "Establish the live region before updating its content." and "The most reliable way to ensure that live regions are registered is to include them in the initial markup." The region is a sibling of the input, outside the popover, so it exists before the list opens; the visible row is `aria-hidden` so it is not read twice (judgement call against Base UI's `Empty` inside the popup).
- **Contrast.** Option text `color-text-default`, group label `color-text-subtlest`, empty text `color-text-subtle`, icons `color-icon-subtle` / `color-icon-accent`, all in the contrast matrix on `surface-floating` and on `background-selected` (the highlight; `background-neutral-subtle-hovered` equals the dark Material, so it would vanish); the Material is a 90 % fill of the floating surface (DropdownMenu spec, inference). Disabled text is exempt (WCAG 2.2 1.4.3).
- **Targets.** Options are `size-control-sm` tall (28, larger on coarse pointers); the field box follows `size-control-md|lg`.
- **More contrast:** `color-text-subtlest` steps up to `color-text-subtle` (token media override); the field box is TextField's. One rule steps option icons from `color-icon-subtle` to `color-icon-default`, as DropdownMenu.
- **Forced colors:** the field box draws TextField's 1 px `CanvasText` border; the list gets a 1 px `CanvasText` border (Material and shadow disappear); the highlighted option sets `Highlight` / `HighlightText` explicitly; disabled options use `GrayText`; the check and icons use `currentColor`.
- **Reduced transparency:** `color-material-thick` turns solid (token media override) and the list sets `backdrop-filter: none` in the same query, as Popover.

## RTL

Logical properties only: the search Icon at the inline start of the field box; each option's icon at the inline start and its check at the inline end. Positioning (spike #4 recipe, Q4-2): `margin: 0; position-anchor: auto; inset: auto; inset-block-start: anchor(self-end); margin-block-start: var(--ab-combobox-list-offset); inset-inline-start: anchor(self-start); min-inline-size: anchor-size(self-inline); position-try-fallbacks: flip-block`; never `position-visibility`. The list inherits `dir` in the top layer (spike #4: "a popover inside a `dir="rtl"` element matches `:dir(rtl)` … while it is in the top layer"). The input's own text direction is `dir="auto"` (TextField). `transform-origin` is mirrored with `:dir(rtl)`. `check` and `search` are not mirrored (Icon spec).

## Feedback events

None. Choosing is a selection, not a toggle or a command (brand book: "Soft synthesised clicks mark toggles, toasts and running a command."; Select precedent), and typing is high-frequency. A product that wants a sound can listen to `onValueChange`. No `src/events/events.ts` entry.

## Testing

User-centric only (brief, hard rule). Story tests assert what a user or assistive technology perceives: the input's role `combobox`, name, description and `aria-expanded`; the listbox's options by role and name, their order and presence after typing (this is how Ranking is tested: prefix before word start before subsequence, ties in document order, accent- and case-insensitive matches in en-US and ro-RO, keyword matches, hidden non-matches, empty Groups gone, "No results" shown and announced); which option is `aria-selected` and referenced by `aria-activedescendant` after typing, arrows and pointer moves; the input's text and the submitted `FormData` after choosing, Tab, Escape and Escape again; focus staying on the input; an enclosing Dialog staying open on Escape; `onValueChange` / `onInputValueChange` / `onOpenChange` values and `details.reason`; the error after Tab with nothing chosen; screenshots of the open list in every variant (open state is the end state of `play`).
