# @abereghici/ui is published as a per-file build; the workspace keeps consuming source

`@abereghici/ui` keeps one subpath per component and no root entry (ADR-0006), but npm consumers get a build, not TypeScript: Next.js and Node don't compile code inside `node_modules`, and React Compiler output has to ship in the package because consumers don't run the compiler on dependencies. tsdown (Rolldown, the engine Vite 8 uses) transpiles every source file to its own output file, like Base UI, Radix and MUI ship theirs: relative imports stay external, so each file keeps its `"use client"` directive, its imports and its own CSS file, and re-export-only modules are emitted as written, because Rolldown's linker turns `export * as Dialog from` into an object holding every part and `export { Root } from` into an import, and Next then ships every part as a client module. React Compiler runs only on `"use client"` modules, because compiled code can't run in a Server Component. `exports` still point at `src/` for Storybook, Vitest and the fixture app, and `publishConfig.exports` points packed packages at `dist/`. We rejected Vite library mode, which merges every component's CSS into one file, and `tsc` emit, which needs a script to build CSS Modules and has no React Compiler pass. The cost: a build step before publishing, and the fixture app tests the source path, so checking the published shape means installing the packed tarballs into a Next.js app.
