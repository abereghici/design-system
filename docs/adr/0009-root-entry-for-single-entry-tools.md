# @abereghici/ui adds a generated root entry for tools that need one entry

`/design-sync` bundles a library from one entry file, so `@abereghici/ui` publishes a `.` entry, `src/index.ts`, that `pnpm entry` generates with one `export *` per public subpath. ADR-0006 rejected a root barrel because each import would parse the whole library and esbuild keeps what it can't prove unused; that cost now falls only on code that imports the root, and the per-component subpaths stay the documented imports. Next and Vite (Rolldown) tree-shake an import from the root to the JS and CSS of the subpath; esbuild tree-shakes the JS but keeps the CSS of every re-exported component. We rejected a sync-only entry outside `exports`, which would leave npm consumers without one entry. The cost: the root is public API, so removing it is a breaking change.
