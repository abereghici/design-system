# Base stylesheet and foundations pages (ticket #12)

What `@abereghici/ui/base.css` contains and why, how the foundations pages read the tokens, and one build trap found on the way. Sources were fetched on 2026-10-24. Baseline statuses come from the webstatus.dev API (`https://api.webstatus.dev/v1/features/<id>`) on the same day.

## The stylesheet

`packages/ui/src/base/base.css`, exported as `@abereghici/ui/base.css`. Apps opt in by importing it after the layer order statement and `@abereghici/tokens/tokens.css`. Everything sits in two layers. Spec #1: "Layer order `ab.reset, ab.tokens, ab.base, ab.components`, declared first by the app." So components and any unlayered app CSS win over every rule here. The `yields to unlayered app CSS` story test checks this: a type selector (0,0,1) beats the base `:focus-visible` (0,1,0).

### `ab.reset`

The reset is a subset of Josh Comeau's "custom CSS reset" (https://www.joshwcomeau.com/css/custom-css-reset/). Its code reads: "`*, *::before, *::after { box-sizing: border-box; }` … `img, picture, video, canvas, svg { display: block; max-width: 100%; }` … `input, button, textarea, select { font: inherit; }` … `p, h1, h2, h3, h4, h5, h6 { overflow-wrap: break-word; }` … `@media (prefers-reduced-motion: no-preference) { html { interpolate-size: allow-keywords; } }`".

| Rule                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Baseline                                  |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `*, ::before, ::after { box-sizing: border-box }`                                                      | The reset's rule 1. It is the only selector on `*`. The modern-web-guidance `css` guide says "DO NOT use global resets (styles on `*`) as they cannot be overridden by web components or lower-priority cascade layers". Neither applies here: spec #1 has no web component layer, and `ab.reset` is the lowest layer.                                                                                                                                                                                                                 | box-sizing: widely                        |
| `body { margin: 0 }`                                                                                   | Only the body margin is removed. The reset's `*:not(dialog) { margin: 0 }` is left out because of the same guide rule, and because it would strip paragraph and heading spacing from app content.                                                                                                                                                                                                                                                                                                                                      | —                                         |
| `:where(img, picture, video, canvas, svg) { display: block; max-inline-size: 100% }`                   | The reset's rule 6, written with a logical property (spec #1: "logical properties only").                                                                                                                                                                                                                                                                                                                                                                                                                                              | widely                                    |
| `:where(input, button, textarea, select) { font: inherit; letter-spacing: inherit }`                   | The reset's rule 7. `letter-spacing` is added because `font` doesn't set it, and the HTML rendering section resets it on controls: "input, button, textarea { letter-spacing : initial ; word-spacing : initial ; line-height : initial ; }" (https://html.spec.whatwg.org/multipage/rendering.html#form-controls). Type roles carry their own letter spacing.                                                                                                                                                                         | widely                                    |
| `:where(p, h1…h6) { overflow-wrap: break-word }`                                                       | The reset's rule 8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | overflow-wrap: widely                     |
| `interpolate-size: allow-keywords` on `:root`, inside `@media (prefers-reduced-motion: no-preference)` | MDN: "The interpolate-size value is inherited, so animating to (or from) an intrinsic size value can be enabled for an entire document by setting it on the document root" (https://developer.mozilla.org/en-US/docs/Web/CSS/interpolate-size). The media condition is the reset's. The brand book also says "Reduced motion removes movement, scaling, blur and stagger", and a size change is movement. The guide `animate-to-intrinsic-sizes` agrees: "MANDATORY Copy-Paste Safety: Disable sizing animations for sensitive users". | **limited** (Chrome/Edge only), see Q12-1 |

### `ab.base`

These rules are adapted from the source design system's own `archived/tokens/base.css` (claude.ai artifact), which is "Element defaults. Reads tier 2 and tier 3 only."

| Rule                                                                                                                                       | Source / reason                                                                                                                                                                                                                                                                                                                                                                    | Baseline                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `:root { scrollbar-gutter: stable }`                                                                                                       | Ticket AC. MDN: "When using classic scrollbars, the gutter will be present if overflow is auto, scroll, or hidden even if the box is not overflowing. When using overlay scrollbars, the gutter will not be present" (https://developer.mozilla.org/en-US/docs/Web/CSS/scrollbar-gutter). This matches the brand book's "Locking scroll never shifts the layout".                  | newly (2024-12-11)                                            |
| `:root { scrollbar-color: var(--ab-color-border-default) transparent }`                                                                    | From the source base.css. `border-default` passes 3:1 on every surface in the contrast matrix. The guide `browser-ui-theming` says: "keep the thumb visibly distinct from the track (≥3:1)".                                                                                                                                                                                       | newly (2025-12-12)                                            |
| `:root { accent-color; caret-color }`                                                                                                      | From the source base.css: accent-bold and text-accent.                                                                                                                                                                                                                                                                                                                             | accent-color: **limited**; caret-color: widely                |
| `:root { background-color; color }`                                                                                                        | The page colors. The source set them on both `html` and `body`. Only the root is set here, because a root background paints the canvas.                                                                                                                                                                                                                                            | —                                                             |
| `body { font: var(--ab-type-body-md); letter-spacing: … }`                                                                                 | Ticket AC "body type". The type role is applied as the token README says: `font` plus its letter-spacing token.                                                                                                                                                                                                                                                                    | —                                                             |
| `:where(table, time, output, data) { font-variant-numeric: tabular-nums }`                                                                 | From the source base.css: "tabular figures wherever numbers are compared".                                                                                                                                                                                                                                                                                                         | widely                                                        |
| `:where(h1…h6) { text-wrap: balance }`, `:where(p, li, blockquote, figcaption) { text-wrap: pretty }`                                      | Ticket AC `text-wrap: pretty`. The guide `improve-text-layout-and-legibility` says to use `balance` on headings and `pretty` on "`<p>`, `<blockquote>`, `<li>`", and "DO NOT apply `text-wrap: balance` globally". MDN on `pretty`: "intended for body copy where good typography is favored over performance" (https://developer.mozilla.org/en-US/docs/Web/CSS/text-wrap-style). | balance: newly (2024-05-13); pretty: **limited** (no Firefox) |
| `:focus-visible { outline: var(--ab-focus-ring-width) solid var(--ab-color-border-focused); outline-offset: var(--ab-focus-ring-offset) }` | From the source base.css, and brand book rule R6 ("Patterns that aren't components (selection, highlight, focus) consume tier 2 directly"). The guide `accessibility` says: "Prefer `outline` over other properties (e.g. `box-shadow`) for focus rings" and "Pair focus outlines with `outline-offset`".                                                                          | widely                                                        |
| `::selection { background-color: highlight; color: on-highlight }`                                                                         | From the source base.css (R6). MDN lists `color` and `background-color` as allowed properties (https://developer.mozilla.org/en-US/docs/Web/CSS/::selection).                                                                                                                                                                                                                      | **limited** (status only; supported in every desktop engine)  |

Left out of the source's base.css (inference: none of these is in the ticket):

- `-webkit-text-size-adjust` / `text-size-adjust`. The unprefixed property is "limited" (Chromium only), and iOS needs the prefix, which would be a fallback (ADR-0002).
- `-webkit-font-smoothing` and `-moz-osx-font-smoothing`. These are non-standard prefixed properties.
- `text-rendering`, `font-kerning: normal` and `font-optical-sizing: auto`. Two of these are already the initial values.
- `font-synthesis-*`.
- The `a` rules. These read `--ab-link-*` component tokens, so they belong to the Link component (Phase 1).

### Tests (packages/ui/src/base/base.stories.tsx)

Each test checks computed styles against token-source literals, in all six projects. Every test was seen to fail under a mutation:

| Mutation                              | Fails                                                                                                                       |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Remove `text-wrap: pretty`            | Chromium and WebKit, both projects. Firefox has no `pretty`, so the test checks it only where `CSS.supports` says it exists |
| Remove `text-wrap: balance`           | All engines                                                                                                                 |
| Make `interpolate-size` unconditional | `chromium-reduced-motion` instance                                                                                          |
| Remove `interpolate-size`             | `storybook (chromium)`, the only engine that has it                                                                         |
| Remove the `::selection` background   | All engines                                                                                                                 |
| Remove `font: inherit`                | All engines                                                                                                                 |
| Remove `scrollbar-gutter`             | All engines                                                                                                                 |
| Unlayer `ab.base` (`@media all`)      | The unlayered-CSS test, in all engines                                                                                      |

Observed engine differences: WebKit serialises a 1.6 × 17px line height as `27.200001px`, and it serialises `font-family` names without quotes (Chromium and Firefox quote `"Noto Serif"`). The tests compare numbers, and compare family names with quotes removed.

## Foundations pages

`packages/ui/src/foundations/`: one CSF file and one MDX page per topic. The MDX page attaches with `<Meta of={…} />` and embeds the stories with `<Canvas of={…} />`. Storybook docs say that MDX attaches to a CSF file with `<Meta of>` (https://storybook.js.org/docs/writing-docs/mdx). The content lives in the stories, so the a11y addon (axe), the story tests and #8's screenshots cover every page. MDX alone runs no tests. Foundations metas take `tags: ["!autodocs"]` so the MDX page is the only docs entry.

- **Generated from tokens.** `tokens.ts` reads the DTCG source through the new `@abereghici/tokens/source/*.tokens.json` export. Tables list every token whose name matches a pattern, together with its authored value, its dark value, its media overrides and its `$description`. Swatches, elevations and materials are drawn once in a `data-theme="light"` subtree and once in a `data-theme="dark"` subtree. The prose pages (principles, direction, interaction, personality, Logo and iconography rules) quote the source `project/README.md`, with the spec's renames applied.
- **Contrast matrix.** The matrix lists moved from `src/contrast.ts` into `src/contrast-matrix.ts`, a pure module with no Style Dictionary import, exported as `@abereghici/tokens/contrast-matrix`. The build check and the page now read the same pairs (the 207 from the source, plus 6 that #15 added for Alert) and the same WCAG formula. Text cells are drawn in their own pair colors, so axe's `color-contrast` rule checks the rendered pairs independently. Recoloring a cell's text to `border-subtle` failed the story. The tests pin the source's tightest results: light 4.56 / 3.05, dark 4.58 / 3.06.
- **Concentric radius.** The radius page computes outer − padding = inner from the component tokens that nest corners: DropdownMenu, ContextMenu, SegmentedControl and Command. The source card's "Dialog → card 16 − 4 = 12" has no matching token pair (`dialog-padding` is 24), so it isn't listed.
- **Type specimen (Q10-4).** `type.stories.tsx` `Roles` renders every `typography` token (17 roles) in its role, using Romanian sample text. The test checks that the latin-ext faces loaded (`document.fonts.check(…, "șț")`). With an ASCII-only sample, that test fails in all three engines.
- **Motion.** Curves are static SVG plots computed from the easing values: cubic Bézier, `ease` (CSS Easing 1 defines it as `cubic-bezier(0.25, 0.1, 0.25, 1)`) and `linear()` points. Nothing animates, so screenshots are deterministic.
- **Logo and iconography.** The Logo page renders `@abereghici/ui/logo` at the brand book's 16 · 24 · 32 · 48 px in the interface color, plus brand moss on lichen and brand lichen on moss, with 24px clear space (half the 48px width). Both are followed by the rules and the `logo-*` tokens. The Iconography page shows the rules and the `icon-*` / `size-icon-*` / `stroke-width-*` tokens, and it embeds #11's `Foundations/Icons` gallery story so the 42 glyphs aren't drawn a second time.

## Trap: Vite's default target breaks Themes in built Storybook

`storybook-static` painted the dark-Theme tables light in Chromium, Firefox and WebKit. The computed value of `--ab-color-surface-default` was `#fff`. The cause is in the built CSS: `--ab-color-surface-default:var(--lightningcss-light,var(--ab-palette-sage-0))var(--lightningcss-dark,…)`. Vite's `build.target` defaults to Baseline widely available: "Specifically, it is ['chrome111', 'edge111', 'firefox114', 'safari16.4', 'ios16.4']". `build.cssTarget` has "Default: the same as build.target", and "When build.cssMinify is 'lightningcss' (the default), this option takes precedence over css.lightningcss.targets" (https://vite.dev/config/build-options). Lightning CSS therefore lowers `light-dark()` into toggles. Those toggles resolve where the custom property is declared (`:root`), so `data-theme` subtrees stop switching.

Fix: `build: { target: "esnext" }` in `packages/ui/vite.config.ts` ("'esnext' … will only perform minimal transpiling"). After the fix, the built CSS keeps `light-dark()` and the dark table paints `rgb(18, 21, 15)` in all three engines. Dev mode and Vitest don't minify CSS, so the story tests can't catch this regression. The `paints each table in its own Theme` test still guards dev-mode behaviour.

**Inference, not verified:** a Next.js app that compiles `tokens.css` through Lightning CSS with browserslist targets below `light-dark()` support would hit the same bug. The app tickets should check their built CSS for `--lightningcss-light`.
