# Tool setup: why each config line exists

Audited 2026-10-24 (R1) against each tool's docs and its source at the pinned version. A line stays only when a test or criterion needs it. Everything that restated a default was deleted. Evidence that used to sit in code comments now lives here.

## Storybook 10.6.3 (`packages/ui/.storybook/`)

- `main.ts` is `defineMain` with `framework`, `stories`, three addons, `core.disableTelemetry` and `features.experimentalTestSyntax`.
  - Telemetry: "by setting the `disableTelemetry` configuration element to `true`" (https://storybook.js.org/docs/configure/telemetry).
  - `.test()` "must be enabled via the `experimentalTestSyntax` feature flag" (https://storybook.js.org/docs/api/csf/csf-next).
- `Story.test(name, annotations, fn)` takes story annotations such as `args`, `globals`, `render` and `beforeEach`. The docs show only `test(name, fn)`. The overload is in the 10.6.3 types: `test(name: string, annotations: StoryAnnotations<TRenderer, TRenderer['args']>, fn: TestFunction<TRenderer>): void;` (`storybook/dist/chunk-DzbDykpY.d.ts:765`). Observed: a test with `{ args: { children: "" } }` failed axe with "Buttons must have discernible text (button-name)". So axe runs on annotated tests, and states that used to be exported stories (Disabled, Labelled, Dark) keep their a11y check as tests.
- `parameters.docs.page`: "To replace the default documentation template used by Storybook, you can extend your UI configuration file" (https://storybook.js.org/docs/writing-docs/autodocs). The default page in 10.6.3 (`addon-docs/dist/blocks.js`, `DocsPage`) is Title, Subtitle, Description, Primary, Controls, Stories. Ours differs in two places:
  - `<Stories includePrimary={false} />`, so `Default` isn't drawn twice. The prop exists at `StoriesImpl = ({ title = "Stories", includePrimary = !0 })`.
  - The component spec's Anatomy, States, Keyboard and Accessibility sections, rendered with the `Markdown` block. The block reads the meta title through `useOf("meta", ["meta"])`, which `blocks.d.ts` exports (`declare const useOf`, `declare const Markdown`). Spec #1 story 30 asks each docs page for anatomy, states, keyboard map and accessibility notes. The spec is their single home.
- `options.storySort.order`: "To sort your stories using a custom list, use the `order` array" and "The `order` array can accept a nested array to sort 2nd-level story kinds" (https://storybook.js.org/docs/writing-stories/naming-components-and-hierarchy).
- `parameters.a11y.config.rules`: "Configuration passed to axe.configure(). Most commonly used to configure individual rules", with the example `{ id: 'image-alt', enabled: false }` (https://storybook.js.org/docs/writing-tests/accessibility-testing). `color-contrast` is disabled only when `matchMedia("(forced-colors: active)")` matches. axe 4.14.0 reads the text color as `nodeStyle.getPropertyValue('-webkit-text-fill-color') || nodeStyle.getPropertyValue('color')` (`axe-core/axe.js`, `getTextColor`).
  - Observed in the forced-colors project: the computed `color` of an `h1` was `rgb(0, 0, 0)` on `rgb(255, 255, 255)`. axe reported "foreground color: #eeefe9, background color: #ffffff", which is the authored dark-Theme text on the forced Canvas. The finding is false, and under forced colors the user's palette owns contrast.
  - Every other variant, forced colors included, runs axe again. The internal `storybook/test-provided` key is gone.
- Information architecture (2026-10-24; proposal in notes/storybook-ia.md). Docs quoted at tag `v10.6.3`.
  - Guides and foundations are unattached MDX: "only provide the `Meta` Doc Block without additional props … 'unattached' documentation" (writing-docs/mdx). Token pages use the `ColorPalette`, `Typeset` and `IconGallery` blocks ("The `ColorPalette` block allows you to document all color-related items", api/doc-blocks). `TokenTable` and `ContrastTable` exist because no Doc Block renders a value table.
  - `tags: { _test: { defaultFilterSelection: "exclude" } }`: "you can alter the default behavior of the `_test` tag to exclude tests from the sidebar by default" (writing-stories/tags).
  - `storySort` `method: "alphabetical"` after the `order` list (writing-stories/naming-components-and-hierarchy), so categories and components need no maintained list.
  - `parameters.docs.toc: true` (writing-docs/autodocs, "Generate a table of contents").
  - The component paragraph is TSDoc: "We recommend using JSDoc comments for descriptions" (api/doc-blocks/doc-block-description).
  - `remark-gfm` in the addon-docs `mdxPluginOptions`: "We recommend enabling the `remark-gfm` plugin" for tables, snippet `storybook-main-config-remark-options.md`. remark-gfm 4.0.1 (2025-02-10).
  - `staticDirs: ["./static", { from: "../../tokens/fonts", to: "/fonts" }]`: type `(string | { from: string; to: string })[]` (api/main-config/main-config-static-dirs).
- Theme (`theme.ts`, `manager.ts`, `globals.tsx`, `manager-head.html`).
  - One `create()` per scheme from `tokens.json` literals: "generate a new theme using the `create()` function from `storybook/theming`" (configure/user-interface/theming).
  - `light-dark()` values can't be used. `convert()` calls `curriedOpacify$1(0.2, appBorderColor)` (`storybook/dist/theming/index.js`), and the manager calls polished on `color.secondary`, `background.app`, `barBg`, `barSelectedColor`, `textMutedColor`, `color.defaultText`, `color.inverseText`, `input.background` and `button.background` (`manager/globals-runtime.js:71497`, `core-server/presets/common-manager.js:2617`, `components/index.js:8891`). polished's `parseToRgb` accepts only hex, rgb(a), hsl(a) and named colors, and otherwise `throw new PolishedError(5)` ("Couldn't parse the color string"). Observed: a `light-dark()` `buttonBg` left the manager blank with that error. The values polished never touches are still pinned: the layout root sets `colorScheme: "light dark"` (`manager/runtime.js:10421`), so a `light-dark()` there follows the OS, not the toolbar.
  - The manager follows the Theme global at runtime: `addons.register` with `api.on(SET_GLOBALS | GLOBALS_UPDATED)` (addons/addons-api: "allows you to register an addon and access the Storybook API") and `api.setOptions({ theme })`, typed "Sets the options for the Storybook UI." `setOptions` merges `{ ...theme, ...options.theme }` into the store that `ThemeProvider theme={ensure(state.theme)}` reads (`manager-api/index.js:1328-1336`, `manager/runtime.js:29211`). `addons.setConfig` at runtime would re-emit `SET_CONFIG`, which also resets the layout and sidebar filters (`manager-api/index.js:1339`, `2416`).
  - `manager-head.html`: `<meta name="color-scheme" content="light dark">` and the Figtree latin preload. `managerHead` appends the `@font-face` rules from `@platform/tokens/font-faces`: "Programmatically adjust the manager's `<head>` … For example, load a custom font" (api/main-config/main-config-manager-head). The core preset reads `manager-head.html` first and passes it as `head` (`core-server/presets/common-preset.js:2237`).
  - `brandTitle` carries the Logo `<img alt="">` and the name: with no `brandImage`, `convert()` sets `image: brandImage || (brandTitle ? null : void 0)` and `Brand` renders `dangerouslySetInnerHTML: { __html: title }` inside the link (`manager/runtime.js:24017-24022`).
  - Docs follow the same choice through `parameters.docs.container` (writing-docs/autodocs, "Customize the Docs Container", snippet `storybook-preview-auto-docs-custom-docs-container.md`) passing `theme` to `DocsContainer` (`DocsContainerProps.theme`). The Theme and Direction globals reach `<html>` through the preview channel's `SET_GLOBALS` and `GLOBALS_UPDATED`, so unattached pages follow them too.
  - `colorSecondary` is Sage 400 in dark: the selected sidebar item is `color: theme.color.lightest` on `darken(0.18, theme.color.secondary)` (`manager/runtime.js:22939`), and no Moss, Lichen or Fern step gives 4.5:1 for that text and 3:1 for the row on `surface-raised` (Q-IA-3).
- Core features: "Actions, Backgrounds, Controls, Highlight, Measure & outline, Toolbars & globals, Viewport" (essentials). `features.backgrounds: false` (snippet `essential-feature-disable.md`), because the Theme global owns the surface. Viewport keeps its defaults: `screenshot:w320` selects `mobile1`.
- Addons beyond the three: `@storybook/addon-mcp` 10.6.1 (2026-09-29; 10.6.3 is under two weeks old) with `features.componentsManifest: true`, so agents can list and read components and stories ("Storybook's MCP server connects your Storybook to AI agents", ai/mcp/overview; the docs toolset needs the manifest). Not added: `addon-designs` (no Figma files), `addon-links` (`?path=` links are enough: "you can use the `path` query string").

## Vitest 5.0.5, addon-vitest 10.6.3, Playwright 1.64.1

- `storybookTest()` takes no `configDir`. Its default is `resolve(join(WORKING_DIR, ".storybook"))` with `WORKING_DIR = process.cwd()` (`addon-vitest/dist/vitest-plugin/index.js:2487-2489`). Every runner (package scripts, turbo, `pnpm --filter`, the Docker script) starts in `packages/ui`.
- The `node` project drops `environment: "node"`, because that is Vitest's default.
- One `storybook` project with two Chromium `browser.instances`: `chromium`, then `chromium-reduced-motion` with its own `provider: playwright({ contextOptions: { reducedMotion: "reduce" } })` and `provide: { reducedMotion: true }`. Instances take `name` and `provider` (`BrowserInstanceOption`, `vitest/dist/chunks/plugin.d.*.d.ts:577-584`), and "you need to define the custom `name` value if you are using the same browser name" (https://vitest.dev/guide/browser/multiple-setups). One project is required: when the Storybook UI runs Vitest it sets `VITEST_STORYBOOK=true` (`addon-vitest/dist/node/vitest.js:175`), renames every `storybookTest()` project to `storybook:${configDir}` (`vitest-plugin/index.js:2803-2810`) and filters on that name, so two such projects clash ("Project name … is not unique"). For the same reason `screenshotProjects()` returns none under `VITEST_STORYBOOK`.
  - The reduced-motion check reads `inject("reducedMotion")` in a project-level setup file.
  - Aria snapshots run in the preview's `afterEach` (`.storybook/test/snapshots.ts`), Storybook's hook for "running checks on the final rendered output" (`docs/writing-tests/interaction-testing.mdx`), which receives `canvasElement`. A story opts out with `parameters: { ariaSnapshot: { disable: true } }`, the shape of `parameters.a11y.disable`.
  - `@vitest/coverage-v8` backs the Storybook UI's coverage toggle; every instance is Chromium.
- `mergeConfig(viteConfig, …)` stays, because `@vitejs/plugin-react` is in `vite.config.ts`, which Storybook merges too: "When Storybook loads, it automatically merges the configuration into its own" (https://storybook.js.org/docs/builders/vite).
- `maxWorkers: "50%"`: in Vitest 5.0.5 browser mode "`maxWorkers` is also the budget of pages shared by the active instances" (`vitest/dist/chunks/index.*.js`, `createBrowserPool`), and the default is `availableParallelism() - 1` (`getDefaultMaxWorkers`), so every run opens 9 pages on a 10-core machine across its six instances. Two runs at once (turbo next to another agent) timed Firefox and WebKit proofs out ("Test timed out in 15000ms while waiting for click": 7 and 6 failures, 451 s each; 1 failure, 247 s, on a rerun). With `maxWorkers: "50%"` (5 pages) the same double run passed twice with 0 failures in about 180 s each; a lone run takes about 150 s instead of 104 s.
- `build.target: "esnext"`: Vite's default target makes Lightning CSS lower `light-dark()` (docs/research/base-stylesheet.md; Q12-3).
- Screenshot harness: docs/research/story-screenshots.md. The variants that differ only in browser context are instances of one `screenshots` project, which shares one Vite server ("Every project will use the same Vite server", https://vitest.dev/guide/browser/multiple-setups); `rtl` and `w320` stay projects because their `initialGlobals` belong to `storybookTest()`. The screenshot is taken in the same preview `afterEach` as the aria snapshot, named `<story id>-<variant>`, so Vitest's default paths need no resolvers. Changes from the audit (notes/screenshot-audit.md): `setupFiles` is relative to the project root, the default `configDir` is used, axe is back, `--only-shell` is in CI, and `update-screenshots.yml` has a `concurrency` group.

## size-limit 14.3.0

One `checks(pattern, subpath, limit?)` helper builds a check per public subpath. size-limit's `path` takes a glob, but one entry sums every matched file, so a per-subpath budget needs an entry per file. "**import**: partial import to test tree-shaking. It could be … `*` to test all exports" and "**ignore**: an array of files and dependencies to exclude from the project size calculation" (https://github.com/ai/size-limit, README at 14.3.0).

## Turborepo 2.11.10

- Defaults (https://turborepo.dev/docs/reference/configuration): `inputs` "Default: `[]`, all files in the package that are checked into source control", `cache` "Default: `true`". So `build.inputs: ["$TURBO_DEFAULT$", ".env*"]` went (no package reads `.env`), and so did the `dev` and `test:watch` tasks (no package defines them).
- `$TURBO_EXTENDS$` "changes this behavior to **append** instead of **replace**". The root `test` and `size` now have no `dependsOn`, so the package files list `["^build"]` directly.
- `apps/ui-next-fixture` `test` depends on its own `check-types`. `check-types` runs `next typegen` (writes `.next/types`) and `test` runs `next build`, which rewrites `.next`. Run in parallel, they raced on that directory (ORCHESTRATION.md, "check-types vs test share .next").

## pnpm 12.15.0

- `trustPolicy: no-downgrade`: "pnpm will fail if a package's trust level has decreased compared to previous releases" (https://pnpm.io/settings/dependency-resolution). semver 6.3.1 arrives via `@storybook/react-vite` 10.6.3 > react-docgen 8.0.4 > @babel/core 7.29.7 and fails that check, so it is listed in `trustPolicyExclude`: "excluded from the trust policy check. This allows you to install specific packages or versions even if they don't satisfy the `trustPolicy` requirement" (https://pnpm.io/settings/dependency-resolution) (Q7-1).
- `@playwright/test` left the catalog with `apps/spike-rsc-namespace`, its only user.

## oxfmt 0.74.0

Every option the old config set was the default (https://oxc.rs/docs/guide/usage/formatter/config-file-reference.html: printWidth 100, tabWidth 2, … sortPackageJson true, sortImports false). Observed: with only `ignorePatterns: [".claude/"]`, `oxfmt --check` flagged the same three docs files as the full config did. `ignorePatterns`: "Patterns use gitignore-style matching, rooted at the directory containing the configuration file."

## Oxlint 1.89.0

- `no-restricted-imports` with `patterns: [{ regex, message }]` bans relative imports of `.storybook` from `src/**`. "The `regex` property is used to specify the regex patterns for restricting modules" (https://oxc.rs/docs/guide/usage/linter/rules/eslint/no-restricted-imports.html). Proved with a probe file `src/button/probe.ts` that imported `../../.storybook/test/listen.ts`: it failed with "import is restricted from being used by a pattern".
- `typescript/prefer-readonly-parameter-types` is off for React code. typescript-eslint: "This rule is very strict on what it considers mutable" and "If your project does not attempt to enforce strong immutability guarantees of parameters, you can avoid this rule" (https://typescript-eslint.io/rules/prefer-readonly-parameter-types/). React treats props as "read-only snapshots in time" (https://react.dev/learn/passing-props-to-a-component).
- `import/no-unassigned-import` allows `**/*.css` (https://oxc.rs/docs/guide/usage/linter/rules/import/no-unassigned-import.html).
- `jsx-a11y/no-noninteractive-element-to-interactive-role` takes eslint-plugin-jsx-a11y's recommended options verbatim, which include `table: ['grid'], td: ['gridcell']` (`src/index.js`, https://github.com/jsx-eslint/eslint-plugin-jsx-a11y/blob/main/src/index.js). Oxlint's defaults are "matching the `eslint-plugin-jsx-a11y` recommended config" by its own comment but list only `ul`, `ol`, `li` and `fieldset` (`no_noninteractive_element_to_interactive_role.rs`, https://github.com/oxc-project/oxc), so the Calendar's APG `<table role="grid">` ("Since the grid role is applied to a table element, the row, columnheader, and gridcell roles do not need to be specified", https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) failed.

## TypeScript 7.0.2

- `packages/ui/tsconfig.json` includes `".storybook/**/*"`. With the bare entry `".storybook"`, `tsc --listFilesOnly` listed only the 6 `.storybook` files reachable by import, and the type-aware lint reported `error`-typed CSS Module members in the rest. With the glob it lists 33.
- `typescript-config/node-library.json` had no user after packages/design-sync was deleted.
- `react.json` adds `esnext.intl` to `lib`: TypeScript 7.0.2 declares `Intl.Locale` `getTextInfo(): TextInfo` and `getWeekInfo(): WeekInfo` only there (`lib/lib.esnext.intl.d.ts`), and web-features 3.44.0 has `intl-locale-info` at Baseline low since 2026-07-21, so `date.ts` and `direction.ts` call them without guards. The lib also references `esnext.temporal`; runtime Temporal still comes from the ponyfill (ADR-0004). A `declare global { namespace Intl }` augmentation instead fails oxlint `typescript/no-namespace`.

## Style Dictionary 5.7.0

- `usesDtcg` is detected: `if (... this.usesDtcg === undefined) { this.usesDtcg = detectDtcgSyntax(this.tokens); }` (`lib/StyleDictionary.js:240-241`). The output with the flag removed is byte-identical (`cmp dist/tokens.css`).
- Durations use the built-in `time/seconds` transform, which outputs seconds (`70ms` becomes `0.07s`); CSS and the Toaster read both units.

`reactCompiler: true` (https://nextjs.org/docs/app/api-reference/config/next-config-js/reactCompiler) is the only option. `browserslist` is explained in docs/research/turbopack-tree-shaking-react-compiler.md.

## Test literals

The colour and size literals the tests assert are the token source's resolved values (`packages/tokens/src/tokens/*.tokens.json`). In `packages/tokens/src/*.test.ts` they are the source artifact's own values: `project/tokens.json` version 1792790791-a4da, `color.css`, `palette.css` and `elevation.css`. `fonts.test.ts` follows Google Fonts' sheet for the same families (docs/research/variable-fonts.md). The comments that mapped each literal to its token are gone. To check a literal, resolve the token named in the test.
